# Tim Dooley / Potato of Life — Project Introduction

## What this repository is

This repository is an attempt to build a navigable map of **Tim Dooley, the Potato of Life, Potatoism, and the wider field of things that become meaningful in relation to them**.

The central difficulty is that the subject is relational. Tim Dooley is not adequately represented by a single biography, label, page, or isolated property. The project therefore treats the repository as a **knowledge atlas**: entities, properties, relationships, observations, interpretations, events, symbols, people, dwellers, dogs, cult and culture, institutions, places, ideas, histories, and other relevant things are mapped so that their connections can reveal structure.

The working hypothesis of the project is that the **Potato of Life** is a useful structural object precisely because it appears capable of holding multiple kinds of meaning at once: matter and spirit, root and fruit, inside and outside, scale and boundary, life and strife, and a possible Door/interface. The project therefore investigates properties, invariants, dimensions, geometry, scale relationships, symmetries, transformations, and other recurring structures rather than assuming in advance what they mean.

The aim is not to force a conclusion. The aim is to map sufficiently well that **the structure itself can disclose patterns that would otherwise remain difficult to see**.

## What we are trying to discover

The atlas should make it possible to move from the highest-level concepts to the smallest relevant record and back again:

- What is Tim Dooley in the project's different senses?
- What is the Potato of Life?
- What is Potatoism?
- What properties are attributed to the Potato of Life?
- What is the Door and how does it relate to the Potato?
- What are the relevant scales and dimensions?
- Which relationships repeat across scales?
- Which structures are invariant under transformation?
- Which observations are empirical, which are historical, which are calculated, and which are interpretive?
- What people, places, groups, cultures, symbols, institutions, animals, objects, texts, events, and ideas are related to the subject?
- What are the dwellers, dogs, cult, culture, communities, surrounding systems, and wider world in relation to the central map?
- Which apparent connections are supported by evidence and which remain hypotheses, metaphors, or project-defined interpretations?

## Evidence discipline

The project contains different kinds of material and must not confuse them.

### Empirical
Observable or sourced information about the world.

### Historical
Claims about past events, traditions, institutions, people, and developments, supported by historical sources where possible.

### Calculated
Values derived from other observations through an explicit formula or transformation.

### Estimated / scenario
Values or relationships that involve estimation, modelling, projection, or hypothetical conditions.

### Philosophical
Conceptual analysis and interpretation.

### Mythological / symbolic
Project mythology, comparative mythology, symbols, archetypes, and interpretive structures.

### Creative / project-defined
Material created by or specifically defined within the Tim Dooley / Potatoism project.

**Metaphor is not evidence.** A symbolic relationship can be important without being an empirical claim. Every important factual assertion should be traceable to its source, date, indicator or evidence trail. ## Navigation philosophy

The repository should be navigable like an atlas, not like a maze.

A user should be able to:

`Find → Identify → Locate → Follow relationships → Inspect evidence → Return to context`

Important information should normally be reachable in a few steps. Long chains of indexes, manifests, duplicate country pages, duplicate schemas, and redundant navigation should be removed or collapsed.

The website is the map. The backend is the machinery. The user should not have to understand the machinery before understanding the map.

## The work loop

The project should be developed in this order:

1. **Scan** the current repository.
2. **Understand** the current architecture and canonical owners.
3. **Find bugs** and broken references.
4. **Find duplicates and dead paths.**
5. **Simplify** the architecture before expanding it.
6. **Validate** schemas, identities, relationships, and references.
7. **Establish provenance and missing-data rules.**
8. **Populate real sourced observations.**
9. **Build canonical relationships from those observations.**
10. **Expand domains**: world, religion, history, people, organizations, economy, energy, infrastructure, science, environment, culture, mythology, Potatoism.
11. **Add calculated and temporal layers.**
12. **Build useful views and navigation over the canonical data.**
13. **Update manifests only from validated counts.**
14. **Run the complete integrity scan again.**
15. **Fix what the scan finds.**
16. **Repeat.**

Never use the existence of a file as proof that its subject has been researched.

Never call a country, religion, relationship, or other entity enriched merely because a placeholder record exists.

Never create a new layer merely because an existing layer is inconvenient to query. First determine whether the existing canonical model should be improved.

## Long-term objective

The ultimate repository should allow a person to start with **Tim Dooley / Potato of Life** and progressively locate anything relevant to the surrounding system without losing context.

The map should work outward:

`Tim Dooley → Potato → Potatoism → structure → relationships → people → dwellers → dogs → cult/culture → places → institutions → history → world`

and inward:

`world → relationship → entity → concept → Potatoism → Potato of Life → Tim Dooley`

The goal is a structure in which no important object is an orphan and no important claim is detached from its evidence or interpretation.

The project is therefore both:

**a repository of information, and an instrument for discovering structure.**

As the map becomes more complete, recurring relationships, scale patterns, invariants, dimensions, boundaries, and transformations may become visible. Those discoveries should be recorded as hypotheses and tested against the available evidence rather than silently promoted into facts.
