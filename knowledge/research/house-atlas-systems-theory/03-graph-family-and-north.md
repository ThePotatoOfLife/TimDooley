# Graph Family and North Formalization

**Status:** exploratory research; non-canonical.

## The House is not one graph

A useful descriptive object is:

`H=(V,T_N,E_B,E_R,E_P,E_T,A,Pi,Sigma)`

where `V` are stable identities, `T_N` is the canonical North tree, `E_B` other broader contexts, `E_R` typed Roads, `E_P` provenance dependencies, `E_T` temporal/version relations, `A` artifacts, `Pi` projections and `Sigma` schemas/invariants.

This describes structures already present in different repository layers. It does not require nine new databases.

## One North inside a richer context graph

A subject can legitimately belong to several broader contexts while still having one privileged canonical North parent for stable orientation.

Treat the North tree as a selected rooted arborescence embedded in a richer context graph:

`T_N ⊆ B`

This gives:

- one stable canonical parent;
- many other broader contexts as typed Roads or Views;
- many lateral relations;
- a reader arrival path that may differ from canonical ancestry.

Expression:

> **One North can be a selected arborescence inside a richer reality.**

This is a mathematical way to preserve one-North simplicity without pretending reality itself has only one meaningful context.

## Sticky parenthood

Canonical re-parenting should be conservative because it changes orientation, breadcrumbs, mental models and downstream structure.

Use a hysteresis principle: a new parent should be materially better than the current one before re-parenting occurs. Lateral contexts can change much more freely.

Do not create an automatic scoring algorithm yet; preserve the policy first.

## Different graph layers answer different questions

### North graph
Rooted directed tree/arborescence for stable orientation. No cycles; every non-root has one parent; every node reaches root.

### Broader-context graph
Allows other legitimate larger contexts without competing with canonical North.

### Semantic Road graph
Typed directed multigraph for part-of, depends-on, compares-with, influenced-by, located-in, funded-by, authored-by, supports, contradicts and other ordinary relations. Cycles are often legitimate.

### Provenance graph
Tracks how current claims/syntheses derive from sources, artifacts and transformations.

### Temporal graph
Tracks versions, validity, first attestation, role change and development.

### Quantitative flow graph
Directed weighted temporal graph for money, energy, trade, information, migration or other dimensioned flows.

### Argument graph
Tracks support, attack, qualification and contradiction among claims/inferences.

### Build dependency graph
Tracks which generated outputs depend on which inputs and supports impact analysis/rebuild.

Critical rule:

> **Centrality, distance, community and cycles only have meaning relative to the selected graph.**

A globally central node is not automatically true, authoritative, causal or the best next navigation step.

## Relation records

Some relationships carry too much structure to remain a bare pairwise edge.

A relation should become a first-class record when the relation itself has substantial attributes, evidence, several participants, or history.

Examples include contracts, acquisitions, treaties, memberships, financial instruments, source transformations and multi-party events.

Expression:

> **A relation earns identity when the relation itself has history.**

## Search, graph, navigation and ownership are different objectives

Do not reuse one ranking for everything.

- Search asks what best answers a query.
- Graph analysis asks what is structurally relevant under a chosen graph.
- Navigation asks what next step best preserves orientation.
- Canonical ownership asks where durable knowledge belongs.

Expression:

> **Search relevance, graph relevance, navigation relevance and canonical ownership solve different problems.**
