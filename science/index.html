SCIENCE

The scientific side of the project asks what can be made precise, what can be measured, and where a symbolic idea stops being a scientific claim.

Can these ideas be formalized?

Some can. A formal model names variables, relations, assumptions and operations clearly enough that another person can inspect the mathematics. Formalization can sharpen an idea without proving that the idea describes nature.

What is a model—and what is only an analogy or metaphor?

A mathematical analogy can reveal shared structure while still referring to different things. Metaphor can organize thought without supplying measurements. The library therefore distinguishes formal model, mathematical analogy, symbolic metaphor and established scientific result.

What can actually be tested?

A scientific claim becomes stronger when it identifies observable consequences, competing explanations and conditions under which it could be wrong. Testing and falsifiability matter more than how suggestive an equation looks.

A symbolic correspondence is not evidence merely because it can be written mathematically.

Where did an equation come from?

The archive separates established equations, Tim-attributed formulations, recovered historical material and later archive-derived extensions. Provenance matters because reconstructing an idea later is not the same as recovering the original equation.

Can theological language become physics?

Not by relabeling scientific terms. Father, Son, Spirit, Door, Axis or Spudlight may motivate comparisons, but physical claims require operational definitions and evidence independent of the religious interpretation.

How does a scientific idea mature here?

The project now uses a claim ladder: description → measured pattern → formal model → calibrated model → discriminating test → replication/generalization → mechanistic support. An idea can be valuable at an early level without being presented as though it has already reached a later one.

What makes a test meaningful?

A serious test names the observable variables, data source, measurement procedure, baseline and alternative models, parameter-estimation method, uncertainty, success criterion and failure criterion. Where meaningful it also uses negative controls, holdouts or out-of-sample checks.

What should happen when a model fails?

Failure narrows, revises or demotes the claim. The archive should keep null results and residuals because they constrain later theory. A failed prediction should not be converted automatically into symbolic confirmation.

What are the main uncertainty types?

Measurement, sampling, parameter, structural, provenance and interpretive uncertainty are kept separate. A precise equation does not remove uncertainty in the data, model form or meaning assigned to the result.

Four examples of what “test it” actually means

The point is not that these project models are already validated. The point is to make the standard of evidence explicit enough that failure is possible.

Spiral versus circle

Claim: recurrence includes a real change of state rather than simply returning around a loop.

measure repeated phase → predeclare a non-returning coordinate → compare change against uncertainty → fit simpler periodic baseline

Failure: no reproducible state change beyond noise, or the “changing coordinate” is chosen only after seeing the trajectory.

Garden versus dependence

Claim: support creates durable local capability rather than permanent reliance on a central helper.

measure capability before → provide support → reduce support → measure retained function / choice / resilience

Failure: outcomes collapse when the center withdraws, or participant capability and exit options never improve.

Corroboration versus copying

Claim: ten references may still be one evidence root.

trace citation/repost lineage → collapse shared upstream roots → recount independent access/witnesses → compare later correction rate

Failure: source-root deduplication provides no gain in distinguishing reliable from fragile claims.

Symbolic mapping versus hindsight

Claim: a mapping is unusually structured rather than one of many equally plausible post-hoc correspondences.

declare mapping rules → generate alternative/permuted mappings → score all by the same criteria → test on new cases

Failure: many alternatives fit just as well or rules change case by case.
