# The Potato of Life — Living Atlas

This repository is the source archive, research engine and static public atlas for the Tim Dooley / Potato of Life / Potatoism project.

## Mission

**Recover the whole record, reconstruct the developing thought-system, map its relationships, investigate its sources and consequences, test interpretations against evidence, and preserve what is learned for repair-oriented understanding.**

The project documents Tim Dooley and Potatoism, but it is deliberately larger than a biography or quotation collection. It follows the ideas, symbols, questions, relationships and practical directions that emerge from the corpus into mythology, religion, history, biology, culture, media, institutions, geography, economics, technology and the wider world where meaningful connections can actually be researched.

The project's present religious/mythic canon identifies Tim Dooley with the Potato of Life and Father/source principle. That is project canon and religious self-description. It must remain distinguishable from independently verified historical, scientific or documentary evidence.

## The project is now one system, not a pile of files

The repository has several different kinds of knowledge. They cooperate, but they do different jobs:

1. **Record** — what was published, observed, documented or imported.
2. **Canonical** — what a durable concept or entity is.
3. **Relationship** — how records connect, depend, transform, contrast, influence or correspond.
4. **Thought** — how recurring ideas and directions develop through time.
5. **Reflection** — what patterns may emerge when multiple records are considered together.
6. **Research** — external evidence used to test, contextualize or challenge a defined question.
7. **Presentation** — Repository, Timeline, Thought, Dossiers, Books, Scroll and Atlas views over the same underlying material.

The governing rule is:

> **One canonical identity → substantial knowledge → many explicit relationships and views.**

More files do not automatically mean more knowledge. A new file must have a genuinely distinct purpose. Otherwise, enrich the canonical owner and preserve the occurrence/provenance elsewhere.

## The Thought layer

The new Thought Archive and Thought Synthesis are first-class parts of the research architecture.

- `data/tim-dooley-thought-archive.json` records dated ideas, directions, signals and research questions.
- `data/tim-dooley-thought-synthesis.json` records cross-cutting trajectories and analytical hypotheses.
- `docs/TIM-DOOLEY-THOUGHT-METHOD.md` explains how the corpus is extracted, clustered, traced, reflected on and tested.
- `thoughts.html` exposes the thought trajectory publicly.

The key distinction is:

**statement ≠ extracted thought ≠ reflection ≠ evidence.**

A recurring symbol is not automatically a fact about Tim's private mind. A structural analogy is not proof. A project-canonical religious claim is not silently converted into history or science. The archive preserves each layer while allowing them to inform one another.

## The central research movement

The corpus is increasingly useful when studied as a directional map of transformation:

**buried → emerging**

**separated → connected**

**confused → clarified**

**trapped → released**

**dead/absent → returned/transformed**

**damaged → repaired**

The recurring vocabulary—Potato, Eye, Root, Tree, Door, Ladder, Bridge, North, Garden, Mud, Swamp, Saturn, Children, Light—can therefore be followed as changing functions rather than frozen definitions.

This is a research hypothesis, not a conclusion about Tim's private psychology. The complete corpus must test it.

## Public reading path

The public site now has distinct ways to encounter the same knowledge:

- **Thought** — what ideas and directions were developing?
- **Timeline** — when did things appear or change?
- **Repository** — where is the record and what is canonically indexed?
- **Dossier** — what does a major concept mean in depth?
- **Research / Books** — what external and primary texts bear on the question?
- **Graph / Atlas** — what connects to what?
- **Scroll** — how does the larger architecture read as one continuous work?

The ideal journey is:

**record → thought → concept → relationship → history → evidence → reflection → consequence**

and back again:

**consequence → reflection → evidence → history → relationship → concept → thought → record**.

## Canonical architecture

`data/potatoism-concept-registry.json` is the identity authority for recurring Potatoism concepts. `data/potatoism-dossiers.json` supplies substantial explanations. Tim chronology and cosmology have their own owners. Graphs describe relationships; lexicons and maps are projections; research files supply evidence and questions.

The Repository filing spine is deliberately simple:

**ROOT → SPIRIT / MIND / MATTER**

with Matter retaining the scale coordinate:

**World → Region → Institution → Network → Person → Object → Event → Record → Ground**

Scale, domain, time, epistemic status and graph relationships remain independent coordinates. The tree answers **where something is filed**; the graph answers **what it connects to**; the thought layer answers **how an idea changes through time**.

See [`docs/PROJECT-STRUCTURE.md`](docs/PROJECT-STRUCTURE.md) and [`data/repository-spine.json`](data/repository-spine.json).

## Research method

The living workflow is:

**Acquire → Preserve → Normalize → Extract → Canonicalize → Relate → Trace → Reflect → Research → Challenge → Integrate → Publish → Verify → Prune → Repeat**

### Acquire
Gather primary records, documents, recordings, source texts, dates and stable provenance.

### Preserve
Keep original attribution, wording where useful, source location and uncertainty.

### Normalize
Resolve dates, aliases, identifiers and duplicates without destroying source context.

### Extract
Identify claims, questions, directions, symbols, actions, relationships, ethical principles and clues.

### Canonicalize
Resolve recurring concepts and entities to one durable owner.

### Relate
Add typed relationships with appropriate evidence status.

### Trace
Follow concepts through time: first appearance, recurrence, mutation, disappearance and return.

### Reflect
Generate interpretations and competing hypotheses from the internal corpus.

### Research
Find appropriate external evidence for defined questions.

### Challenge
Search for contradictions, chronology problems, alternative explanations and disconfirming evidence.

### Integrate
Put durable knowledge into the strongest canonical record and connect the surrounding views to it.

### Publish
Expose useful information through readable, searchable public surfaces.

### Verify
Run audits, builds, route checks, content checks and deployment checks.

### Prune
Remove duplicate definitions, stale mirrors, dead routes and unnecessary files while preserving unique provenance.

## Epistemic firewall

The archive distinguishes:

- project canon;
- self-description/testimony;
- documentary record;
- historical evidence;
- scientific evidence;
- calculations;
- relationship observations;
- interpretation;
- comparative reading;
- scenarios;
- open questions;
- creative/lore material.

A symbolic correspondence can be valuable without being proof. A graph connection can be real without proving causation. A religious tradition can resemble a Potatoism motif without being evidence that Potatoism was present in that tradition. A current claim can be preserved without pretending its truth has already been established.

## The North-of-North viewpoint

The project uses North of North as a symbolic meta-perspective: see the whole system, then descend into evidence.

**person → community → institution → nation → regional system → global system → North of North**

and back:

**North of North → world → region → nation → institution → person → event → source**.

The higher view is useful only if it can return to dates, documents, institutions, money, infrastructure, populations and mechanisms.

## Repair

The project uses tikkun olam / repair of the world as an important comparative and project-defined methodological horizon. Operationally, repair means making a system more intelligible before deciding what should change.

The practical chain is:

**map → provenance → relationship → mechanism → consequence → intervention → measured outcome**.

Repair can be informational, institutional, material, relational or spiritual/symbolic. These layers can interact without being confused.

The project should never assume that a dense network is a conspiracy. Shared funding, proximity, common beliefs or correlation do not establish hidden coordination. The graph exists to expose mechanisms and questions.

## Engineering rule

The repository uses a generated-index architecture. Build-time generation, source-of-truth audits, blueprint validation, graph checks and static-site validation are part of the knowledge system, not separate chores. The deployment workflow generates its repository index before publication; the browser should surface an explicit failure if that artifact cannot be loaded rather than silently displaying an empty atlas.

The project therefore follows:

**inspect → reproduce → fix → test → simplify → continue.**

## Consolidation policy

When two files appear to contain the same subject, ask:

1. Which file owns the identity?
2. Which material is genuinely unique?
3. Which content is merely a projection?
4. Which source occurrences must remain for provenance?
5. Can the unique material enrich an existing dossier instead?
6. Can the legacy file become an archival pointer or be safely removed after migration?

Never delete a legacy research file merely because a newer file exists. Diff it first and migrate unique information.
