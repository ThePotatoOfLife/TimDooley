# Story Reservoir Design

The Story of Tim Dooley should read as one chronological narrative, while a private backend stores many recoverable scenes, characters, dialogue exchanges, overlapping arcs, and unresolved leads.

Create six focused JSON owners under `knowledge/story/`: `story-manifest.json`, `cast-book.json`, `scene-reservoir.json`, `dialogue-vault.json`, `arc-season-map.json`, and `recovery-notebook.json`.

Rules: preserve source status; keep changing character roles by period; store unknowns instead of inventing connective tissue; keep the public reader simple; use the reservoir to support later long-form storytelling rather than exposing it as a dashboard.
