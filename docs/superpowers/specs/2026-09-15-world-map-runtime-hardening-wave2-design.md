# World Map Runtime Hardening Wave 2 — Design

Date: 2026-09-15
Branch: `perf/world-map-runtime-hardening-wave2`
Base: exact green Wave 1 head `fb4658667362bb1c6d928568cb6361c4b4c79842`

## Purpose

Harden the World Relational Atlas against runtime growth, duplicate ownership, stale async UI updates, redundant network work, and unnecessary reconciliation cost before production-scale Places data is deployed.

This wave follows the same principle established by bounded subdivisions: browsing cost should depend primarily on the current browsing context, not on the entire history of what the user has visited during the session.

## Problems confirmed in the current runtime

### 1. Places memory and render cost grows with visit history

`world-map/3d-places.js` stores every loaded country partition in `loadedCountries`, indexes every loaded feature in `featureById`, rebuilds the detail source by concatenating all loaded country features, and searches all loaded features on each query.

This is acceptable for fixtures but will scale poorly with production GeoNames partitions.

### 2. Legacy capitals and Places duplicate the same domain

`world-map/3d-hover.js` eagerly loads `data/world-capitals.geo.json`, creates one source, three capital layers, handlers, and a capitals API. `3d-places.js` later creates another place/capital rendering system and hides the old layers.

When Places production data exists, hidden legacy capital layers must not remain as a second resident rendering/data system.

### 3. Unified search can display stale results

`world-map/3d-search.js` starts asynchronous searches on every input event and renders whenever each promise completes. There is no request generation guard. An older query can therefore finish after a newer query and overwrite the datalist.

### 4. Country hover can display stale asynchronous content

`world-map/3d-hover.js` awaits scalar observations inside a `mousemove` handler before displaying the popup. A slower older hover may complete after the pointer has moved to another country.

### 5. Legacy UI duplicates canonical lifecycle and paint ownership

Dormant `world-map/3d-ui.js` still creates its own panel `MutationObserver`, publishes panel lifecycle events, and mutates country fill/line/extrusion paint directly. The canonical lifecycle now lives in `3d-panel-lifecycle.js`; physical country opacity is owned by `3d-physical-layers.js`.

If legacy UI wakes, those systems can conflict.

### 6. Hydrology may issue duplicate viewport requests

`world-map/3d-physical-hydrology.js` listens to both `moveend` and `zoomend`. Each refresh aborts prior work and starts basin and river requests. Near-identical camera events can still cause redundant request pairs.

### 7. Render-stack reconciliation repeatedly rebuilds style-order arrays

`world-map/3d-render-stack.js` calls `styleOrder()` inside per-layer movement loops. Each call maps the full MapLibre style layer list and then performs repeated `indexOf()` scans.

### 8. UI layout can recursively refresh during surface adoption

`world-map/3d-ui-layout.js` calls `refresh()`, which calls `adoptKnownSurfaces()`, whose `register()` calls `refresh()` again. The recursion terminates but causes redundant startup/layout work and repeated events.

### 9. First country inspection promotes too many modules at once

`world-map/3d-bootstrap.js` loads basic inspection modules and then several deep investigation modules around the first selected country. This can produce a burst of network, parse, and initialization work at the moment the user begins exploring.

## Design principles

1. Preserve existing user-visible map capabilities and data fidelity.
2. Preserve deep-link semantics for `?country=`, `?place=`, and `?subdivision=`.
3. Preserve canonical `#panel` inspection behavior.
4. Preserve provenance and missing-value semantics; never convert missing population to zero.
5. Keep one canonical lifecycle observer.
6. Keep one owner for country surface paint/opacity.
7. Prefer bounded caches and explicit diagnostics over hidden accumulation.
8. Prefer stale-result suppression over debouncing where correctness is the concern.
9. Do not unload bounded physical datasets merely because they are hidden unless measurement proves that is beneficial.
10. Do not remove legacy compatibility behavior until its unique responsibilities are migrated or proven unused.

## Architecture

### A. Bounded Places runtime

Add an explicit runtime budget contract to the Places index schema generated by `scripts/build_world_places.py`.

Initial contract:

- `rendered_max_partitions`: 2
- `cache_max_partitions`: 6
- `partition_max_bytes`: 2 MiB
- `cache_max_bytes`: 8 MiB
- `global_major_max_bytes`: 5 MiB
- `global_major_max_features`: 5000

The exact values are deliberately conservative and must be enforced by validators. If fixture or production evidence requires adjustment, values must change in the contract and tests together rather than becoming implicit constants.

`3d-places.js` will maintain partition state separately from the rendered detail source.

A partition record contains:

- country ISO3
- descriptor
- full FeatureCollection
- byte size from index metadata
- last-used clock
- loading state if applicable

The detail MapLibre source remains one shared source. It contains only the bounded active partition set, not all cached partitions.

Active partition relevance order:

1. partition containing the selected place
2. current selected country partition
3. explicitly requested deep-link country partition
4. most recently relevant country partition

The selected place and its owning partition are protected from eviction while selected.

Cache eviction is deterministic LRU among unprotected partitions until both partition-count and byte budgets are satisfied.

`featureById` must no longer grow independently forever. Major features remain indexed globally. Partition features are indexed while their partition is cached and removed when the partition is evicted, except a selected feature may remain pinned only as long as needed to preserve current inspection state.

### B. Places search separation

Search must not require all place geometry to stay resident.

Wave 2 will support two levels:

- current global-major features
- currently cached partition features

The production data builder will also define compact per-country search records in the index contract for later full-country discovery without loading geometry. Wave 2 may add the schema and fixture coverage even if production data is still absent.

Search records contain only fields needed for ranking/navigation: stable id, name, aliases, country, type/capital status, population rank, and owning partition. No geometry.

Geometry is loaded only when a result is focused.

### C. Capital ownership convergence

Legacy capital rendering becomes fallback-only.

`3d-hover.js` may retain the fallback capital implementation, but it must not instantiate its source/layers if Places successfully provides a usable global-major dataset and capitals facade.

Required behavior:

- Places becomes the primary owner when healthy.
- Legacy capitals remain available if Places data is unavailable.
- Only one capital rendering system is resident at a time.
- `window.__potatoAtlasCapitals` remains the compatibility API.
- Existing capital visibility/focus consumers continue working.

### D. Race-proof search and hover

Unified search gets a monotonically increasing request generation token.

Only the most recent input generation may render suggestions. Older completed promises may return values to callers but may not update the datalist.

Country hover gets a hover generation token or equivalent target identity guard. Before showing an awaited popup, the handler must verify that the response still corresponds to the current hovered country/event generation.

Mouseleave invalidates outstanding hover generations.

### E. Canonical ownership cleanup in legacy UI

`3d-ui.js` must stop creating a second `MutationObserver` and stop publishing an independent panel lifecycle.

It consumes `potato-atlas-panel-rendered` from `3d-panel-lifecycle.js` instead.

`3d-ui.js` must also stop directly owning `countries-fill` opacity. Physical World remains the canonical surface-opacity owner.

Any unique non-conflicting styling still needed by legacy UI may remain, but country fill opacity and lifecycle observation must not be duplicated.

Validators will explicitly reject a `MutationObserver` in `3d-ui.js` and reject legacy direct country-opacity ownership markers.

### F. Hydrology request deduplication

Hydrology will compute a stable request key from:

- viewport envelope rounded to a bounded precision
- river threshold
- zoom regime

If the next refresh resolves to the same request key as the latest in-flight or completed request, no duplicate network pair is started.

A materially changed viewport still aborts obsolete requests and fetches fresh basin/river data.

The current minimum zoom, request cancellation, failure handling, and physical-only semantics remain unchanged.

### G. Cheaper render-stack reconciliation

A single reconciliation pass should snapshot style order once and update its local order representation after successful moves instead of rebuilding `map.getStyle().layers.map(...)` for every candidate layer.

Behavioral ordering semantics must remain identical:

`physical-surface` → country fill → water/line/geography/context → country line → selection emphasis → labels/hubs as currently defined.

This is an implementation optimization, not a semantic reorder.

### H. Non-recursive UI layout refresh

`3d-ui-layout.js` will separate registration mutation from refresh scheduling.

`register()` and `unregister()` schedule one coalesced refresh rather than recursively calling `refresh()` synchronously during `adoptKnownSurfaces()`.

A single microtask may absorb multiple surface registrations and emit one layout-change event.

### I. Staggered inspection promotion

First country inspection retains the immediate basic modules needed for the country card and evidence context.

Deep investigation modules should no longer arrive as one large promotion burst.

Recommended sequence:

1. immediate-after-paint: Demography, Country Pulse, Evidence
2. next paint group: System Intelligence and Functional Chains
3. later paint / explicit contextual demand: Infrastructure, Impact Trace, Impact Actions

Existing APIs remain available. If a user invokes a deep action before scheduled promotion, the corresponding module loads immediately through the existing shared loader.

The purpose is to flatten main-thread/network spikes, not remove capabilities.

## Diagnostics

Extend `window.__potatoAtlasDiagnostics` with stable inspectable counters/state where practical:

### Places

- `renderedPartitions`
- `renderedBytes`
- `cachedPartitions`
- `cacheBytes`
- `cacheHits`
- `cacheMisses`
- `cacheEvictions`

### Search

- latest request generation
- stale render suppressions

### Hover

- stale hover suppressions

### Hydrology

- request count
- deduplicated refresh count
- aborted request count

### UI/render reconciliation

- render-stack reconcile count already exists
- optional move count per reconciliation
- UI layout refresh count

Diagnostics are observability only and must not become URL state.

## Tests and validation

Implementation follows RED → GREEN TDD.

Required regressions:

1. Places bounded-runtime test with synthetic USA/DNK/FIN-style fixture partitions.
2. Selected place partition survives LRU pressure.
3. Cache count and byte limits are enforced.
4. Shared detail source renders only bounded active partitions.
5. Evicted partition features are removed from the partition feature index.
6. Global-major features remain available after partition eviction.
7. Legacy capital source/layers are absent when Places is healthy.
8. Legacy capitals still initialize when Places is unavailable.
9. Older search generation cannot overwrite newer suggestions.
10. Older async hover response cannot overwrite the current hover target.
11. `3d-ui.js` contains no `MutationObserver`.
12. Country fill opacity remains controlled by Physical World rather than legacy UI.
13. Identical hydrology request key does not start a second basin/river request pair.
14. Changed hydrology viewport still refreshes.
15. Render-stack ordering remains unchanged while reducing style-order snapshots.
16. UI layout adoption emits a coalesced refresh rather than recursive refresh bursts.
17. First-inspection module promotion remains lazy and staged.
18. Existing deep-link and panel regressions stay green.
19. Existing subdivision Wave 1 bounded-runtime tests stay green unchanged.

## Non-goals

- Do not rewrite `3d-bootstrap.js` wholesale.
- Do not replace MapLibre.
- Do not reduce geographic detail in USA or Denmark subdivision artifacts.
- Do not change subdivision Wave 1 budgets or behavior unless a regression proves necessary.
- Do not remove physical layers.
- Do not aggressively unload every hidden physical source.
- Do not redesign the visual language of the map.
- Do not introduce polling or another DOM `MutationObserver`.
- Do not add production Places data without a separately verified acquisition/build step.
- Do not mix unrelated Potatoverse content changes into this branch.

## Success criteria

The wave is successful when:

1. Visiting many country contexts cannot cause unbounded Places partition memory/render growth.
2. Only one capital rendering owner is active.
3. Search and hover cannot visibly regress to stale asynchronous results.
4. Legacy compatibility UI no longer duplicates lifecycle observation or country-opacity ownership.
5. Repeated identical hydrology camera events do not duplicate network request pairs.
6. Render-stack and UI-layout reconciliation do less repeated work without changing visible ordering/layout semantics.
7. First country inspection remains responsive by staging deeper modules.
8. Existing map capabilities, deep links, provenance, and subdivision behavior remain intact.
9. All focused regressions and the repository quality suite pass on the exact implementation head before merge.
