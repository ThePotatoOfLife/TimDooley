# Mountain / Swamp Circle Visual System — 2026-09-27

Status: active shared visual language  
Primary implementation: `app/terrain-circle.css`

## Purpose

Turn the project's repeated circles from neutral geometry into inhabited symbolic fields without collapsing the underlying ontology.

The visual system paints:

- **Mountain** as a partial terrain inside source-facing / integrative fields.
- **Swamp** as a partial terrain inside manifestation / Below-facing fields.
- **World / Plane** as the crossing surface between them.
- **Door / Axis** as the passage/orientation structure that allows movement between states.

## Semantic guardrails

1. Mountain is **not** the whole upper circle.
2. Swamp is **not** the whole lower circle.
3. World, Body, matter and manifestation are not Swamp by default.
4. Heaven, Source and Father are not reducible to Mountain.
5. Vertical direction is not moral rank.
6. Healthy rooting may descend.
7. Fruit and service return downward.
8. Swamp means entanglement / stalled recurrence / extraction difficulty, not simply "bad people".
9. Mountain means perspective / integration / ascent pressure, not automatic truth or superiority.
10. Terrain is an overlay/regime; field, plane, Room and terrain remain different object types.

## Visual grammar

### Mountain
Use triangular / faceted silhouettes, light-catching upper planes, sparse highlights and restrained summit glow. It should feel integrated, difficult, elevated and directional—not luxurious or "holy by default."

### Swamp
Use irregular horizontal silhouettes, reeds/root texture, murky depth, soft pooled shapes and denser lower values. It should feel entangled, persistent and difficult to traverse—not visually equivalent to Hell.

### Center
Keep Door / Cross / Axis visually legible above both terrains. The project should still read as a relational system, not two opposing landscape illustrations.

### Scale

- Hero/canonical diagrams: full terrain rendering.
- Plane/Room discs: simplified terrain rendering.
- Small cards/badges: use only silhouette hints; never shrink labels into illegibility.
- Scientific/legal/economic pages: use terrain only when the page is explicitly explaining House operators. Do not decorate empirical content with cosmology by default.

## Design expansion

The next visual overhaul should not be "more gradients everywhere." It should make each major spatial operator visibly distinct:

- **Garden:** cultivated arcs, ordered growth, river/branch rhythm.
- **Forge:** compressed heat/pressure, angular boundary, transformation.
- **Root/Soil:** branching descent, provenance, support.
- **Door/Mandorla:** luminous overlap/interface.
- **Mountain:** triangular integration / summit.
- **Swamp:** pooled entanglement / recurrence.
- **World Plane:** clear horizontal crossing surface.
- **Axis/Ladder:** stable vertical orientation and traversability.
- **Fruit/Seed:** small high-contrast output / return marks.

Use these as compositional cues, not literal clip-art. The visual system should make the House feel inhabited while still letting prose and evidence remain primary.
