# Repository Coverage and Carving Map

## Purpose

This document is the working map for making the archive denser without repeatedly redesigning its architecture. The canonical tree remains fixed. New depth is added underneath existing concepts through research layers, child records, relationships and evidence-bearing datasets.

## Core rule

Every expansion should answer at least one of these questions:

1. **What is it?** — definition and scope.
2. **When did it exist or change?** — temporal history.
3. **Where is it?** — geography and jurisdiction.
4. **Who controls or participates?** — ownership, authority and actors.
5. **What does it connect to?** — relationships and dependencies.
6. **What information does it create or consume?** — information flow.
7. **What records prove it?** — provenance and sources.
8. **What changed?** — event and version history.
9. **What is disputed?** — allegation, counterclaim and evidence quality.
10. **What follows from it?** — downstream consequences.

## Coverage dimensions

### Source / Separation / Ladder / Door / Son

Strengthen the symbolic architecture with textual provenance, comparative religious material, art history, philosophy, psychology and project mythology. Do not turn symbolic interpretation into empirical fact.

### Tree of Life / Tree of Strife

Map the Tree as a relational grammar: root, transmission, branching, exchange, fruit, seed, rupture, shell, trapped value, extraction, fragmentation and repair. Qliphothic material must retain its historical strata: biblical/rabbinic, Zoharic, Lurianic and later Western occult reception.

### Potato

Expand Potatoism through examples of natural growth, recurrence, ecological cycles, memory, food systems, agriculture, soil, logistics, markets and cultural symbolism. Keep the philosophical layer distinct from agricultural facts.

### World

The World layer is the largest empirical field and should continually expand through:

- states and territories;
- cities and ports;
- population and demography;
- law and courts;
- companies and ownership;
- finance and debt;
- energy and materials;
- infrastructure;
- transport and logistics;
- health and biology;
- labour and skills;
- science and technology;
- media and information;
- war and diplomacy;
- religion and culture;
- internet communities;
- intelligence and security institutions.

### North Programme

Each country should eventually have the same analytical template:

`constitution -> institutions -> population -> labour -> tax base -> public spending -> debt -> financial system -> energy -> industry -> infrastructure -> research -> technology -> trade -> strategic dependencies -> alliances -> repair opportunities`

This permits actual cross-country comparison rather than country-by-country prose.

## Intelligence / information network

The intelligence branch should not become an operational manual. It should remain a public-source institutional graph:

`agency -> legal authority -> mission -> collection category -> database/record system -> sharing mechanism -> oversight -> archive -> public record`

A separate event graph should connect:

`case -> date -> actors -> allegation -> investigation -> finding -> evidence -> archive`

This is particularly important for CIA, FBI, NSA, Mossad, CENTCOM, MI6, FSB, Europol and related services because agency identity, military command, police authority, intelligence collection and information exchange are not interchangeable concepts.

## Internet ecology

The online branch should model platforms and communities separately:

`platform -> board/subreddit/forum -> moderators -> users -> content -> archive -> migration -> moderation event -> offline event -> institutional response`

4chan, Kiwi Farms and Reddit should therefore never be represented as equivalent organizations. A platform can host many incompatible communities; a community can migrate between platforms; a symbol can be used by people who do not share the ideology associated with it.

## Event ledger

A repository-wide event ledger is needed because many branches have dates but lack a common temporal spine. The desired minimum schema is:

`event_id, date_start, date_end, location, actors, institutions, action, target, consequence, legal_response, investigation, source, evidence_status, confidence`

## Ownership graph

The ownership layer should distinguish:

- legal owner;
- beneficial owner;
- voting control;
- management control;
- lender/security interest;
- regulator;
- operator;
- concession holder;
- major customer;
- government purchaser;
- infrastructure dependency.

This prevents the common error of treating ownership, influence and regulation as the same relationship.

## Data-flow graph

For information-bearing systems, the minimum chain is:

`origin -> collection -> storage -> processing -> query -> analysis -> dissemination -> decision -> archive`

For public records:

`event -> document -> archive -> index -> researcher -> citation -> interpretation`

For internet information:

`event -> post -> repost -> community -> platform -> archive -> journalist -> institution -> public record`

## Temporal versioning

Important relationships should eventually support:

- `valid_from`
- `valid_to`
- `announced_on`
- `effective_on`
- `source_published_on`
- `last_verified`
- `status`

This is the mechanism for answering questions such as **when a database was introduced, when an agency changed authority, when an alliance expanded, when a company acquired an asset, or when a public archive gained or lost a document**.

## Evidence hierarchy

Use a practical hierarchy:

**A — primary:** statute, court judgment, official database documentation, declassified document, commission report, parliamentary record, contemporaneous record.

**B — strong secondary:** peer-reviewed scholarship, established historical research, major investigative journalism with documentation.

**C — useful secondary:** specialist journalism, reputable archival projects, institutional histories.

**D — lead:** community archive, forum archive, unattributed document, database mirror, social-media claim.

**E — allegation:** claim not independently established.

D and E records can be valuable research leads, but they must not silently become A/B facts.

## Weaknesses to carve next

1. Temporal metadata is still uneven across the repository.
2. Ownership and control are much less developed than entity descriptions.
3. Infrastructure needs asset-level records rather than sector summaries.
4. Intelligence databases need individual system histories, legal bases and sharing edges.
5. The internet branch needs a larger chronology of platform/community migrations.
6. The event ledger needs to connect dates across otherwise separate branches.
7. The religious branch needs more institutional property, demographic and economic data.
8. The Standard Model branch can be expanded into experimental evidence and precision tests.
9. The Qliphoth branch can be expanded through primary-text quotations/references and scholarly historiography.
10. The North Programme needs more country-level fiscal and industrial evidence.
11. The relationship graph needs provenance and temporal validity on more edges.
12. The frontend needs to expose expansion layers without turning the interface into a wall of undifferentiated data.

## Operating principle

Do not ask whether a branch is finished. Ask what the next missing relationship is.

The repository becomes useful when an entity stops being a label and becomes a node with history, jurisdiction, relationships, evidence, dependencies and consequences.
